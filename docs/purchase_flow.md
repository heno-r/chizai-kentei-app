# 購入フロー設計

- 作成日: 2026-04-30
- 対象: 3級プレミアム版

## 目的

購入前ページから購入後のプレミアム解放まで、ユーザーがどこに戻され、何を見て、どの状態で何が使えるかを固定する。

## 状態遷移

### 1. 未購入

状態:

- 無料版は使える
- プレミアム機能はロック
- 購入前ページでは価格、解放機能、利用前提を確認できる

画面:

- `/app/`
- `/premium/`
- `/premium/ready/`

次の行動:

- ログイン
- 購入前チェックを完了
- 購入開始

### 2. 購入中

状態:

- 決済画面へ遷移した直後
- まだプレミアム権利は確定していない

画面:

- 決済プロバイダの checkout
- 戻り先は `購入前チェック` または `購入完了確認ページ`

次の行動:

- 決済完了
- 決済失敗または中断

### 3. 購入成功

状態:

- 決済自体は完了
- ただし権利反映を待つ短い区間がありうる

画面:

- `購入完了`
- `反映確認中`

次の行動:

- secure API が支払い完了を確認
- `entitlements` に `premium` を付与

### 4. ライセンス反映済み

状態:

- `active_plan = premium`
- プレミアム対象機能が解放される

画面:

- `/app/` へ戻る
- もしくは `/premium/` から `プレミアム版を始める` へ進む

次の行動:

- 苦手復習を開始
- 要復習キューを使う
- 直前14日モードを使う

## 推奨する戻り先

### 購入前の主導線

1. `/app/`
2. `/premium/`
3. `/premium/ready/`
4. ログイン
5. 購入開始

### 購入成功後の戻り先

優先順位:

1. `/app/?plan=premium`
2. `/premium/` の完了案内付き表示

理由:

- すぐに使い始められる
- `プレミアム版が解放された` 実感を出しやすい
- `間違えた問題だけ復習` や `要復習キュー` の価値につなげやすい

## 画面ごとの見せ方

### `/premium/ready/`

- まだ未購入なら:
  - `ログインして続ける`
  - `無料版をもう一度試す`
- ログイン済み未購入なら:
  - `購入手続きへ進む`
- 購入成功後:
  - `プレミアム版を始める`

### `/app/`

- 未購入:
  - プレミアム機能はロック表示
- 購入済み:
  - プレミアム機能を解放
  - 初回は `まずは間違えた問題だけ復習がおすすめです` のような案内を出す

## 異常系

### ログイン失敗

- `ログインに失敗しました。時間を置いて再度お試しください。`

### 決済失敗

- `決済は完了していません。無料版はそのまま使えます。`
- 戻り先: `/premium/ready/`

### 決済成功だが権利未反映

- `購入は完了しました。プレミアム版の反映を確認しています。`
- 数秒後に再照会
- だめなら問い合わせ導線

## フロントで必要な最低状態

```json
{
  "signed_in": false,
  "purchase_state": "not_started",
  "active_plan": "free"
}
```

例:

- `purchase_state`
  - `not_started`
  - `in_checkout`
  - `paid_pending_entitlement`
  - `entitled`

## いま決めておく結論

- 購入後の主な戻り先は `/app/`
- 購入完了直後は `反映確認中` を許容する
- 最終的な機能解放判定は `active_plan = premium`
- 購入前ページには `ログイン -> 購入 -> 解放` の流れを見せる
